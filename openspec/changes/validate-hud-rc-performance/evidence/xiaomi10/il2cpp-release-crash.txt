The generated line is in `HudRcPerformanceRunner.BeginRun`, at the initial `GC.GetAllocatedBytesForCurrentThread()` calibration call (source line 134), before holders, meshes, `ProfilerRecorder`, or the measurement loop are created. The first Development/Mono run did not crash, which makes the Android IL2CPP implementation of this per-thread allocation API the leading trigger. This is a runtime compatibility finding, not evidence that the package workload itself is slow.

Remediation: the Sample runner now compiles out all `GC.GetAllocatedBytesForCurrentThread()` calls for `ENABLE_IL2CPP` builds. IL2CPP reports scoped allocation fields as `unavailable` and continues with CPU/frame measurements; Mono/Editor keeps the calibrated diagnostic path.
