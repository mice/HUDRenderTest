# 数字渲染对照阶段归档记录

2026-10-28，按用户要求合并主规格并阶段归档 `compare-damage-text-renderers`。任务完成 **21/22**；`3.1` 保持未完成，正式 GPU/完整帧收益仍为 **unverified**，由 [DAMAGE-03](../../../../Documentation~/todo.md) 承接。本次归档不代表 GPU 门禁、RC 或发布通过，包版本仍为 `0.1.2 Unreleased`。

## 已交付

A 共享 Quad 字符实例化与 B 持久数字 Mesh 使用相同事件、布局、动画和有序提交；提供画面检查、固定序列、实时回放及独立纯绘制/完整生命周期阶段。已交付预注册请求、JSON/CSV 报告、离线有效性检查、隔离 Android 构建、局部 XY FP16 能力/布局/精度回退，以及 opt-in 原生 Vulkan 查询校准和记录通路。Float32 保持默认。

两份增量规格已同步到 [渲染对照](../../../specs/damage-text-renderer-comparison/spec.md)和 [局部 FP16](../../../specs/damage-text-local-fp16/spec.md)主规格，共 9 条需求、15 个场景。

## 对比结论

Mi 10 / Adreno 650、Android 11、Release IL2CPP ARM64 / Vulkan、2340×1080、60 Hz 目标下，同 APK 完成 13 组 ABBA、52 轮、187,450 个正式采样帧；温度 31.7–33.0°C，thermal status 0。包含 2/5/8 位纯绘制、连续生命周期、127/128/129/256 百窗口爆发、低/高重叠、B32/B16 和实时回放。

| 对比范围 | 重复运行的外层 Update CPU 中位数 | 可支持的判断 |
| --- | --- | --- |
| 连续生命周期 A / B32 | A 0.09035 / 0.09370 ms；B32 0.17465 / 0.17055 ms | A 在本负载约少 0.081 ms（约 47%） |
| 256 爆发的实际刷新帧 A / B32 | A 0.53845 / 0.53920 ms；B32 1.06295 / 1.06220 ms | A 的刷新帧成本较低；稀疏整段中位数不能替代刷新帧结论 |
| 连续生命周期 B32 / B16 | B32 0.16860 / 0.17315 ms；B16 0.20265 / 0.20455 ms | FP16 约增加 0.0327 ms（约 19%），未证明整体收益 |

上述计时不含稍后相机回调的命令记录成本，不能作为 GPU 或整帧排名。主线程约 16.7 ms 包含 60 Hz 等待；渲染线程和安全 IL2CPP GC 计数不可用。纯绘制的外层 CPU 只反映计时/调度成本。

FP16 完整 stride 为 68→64 B；该配置理论顶点容量由 4,456,448→4,194,304 B，节约 262,144 B（约 5.9%），并非实测 GPU 内存或带宽。Vulkan 精度检查覆盖 32 场景/640 点：24 场景采用 FP16，最大接受误差 0.11854 px；8 场景超过 0.25 px 候选门槛并正确回退 Float32，最大误差 0.49270 px。美术接受尚未提供。

原生 Vulkan 查询校准的 B32/A32/B16 共 1,680 个所需帧有效并直接绑定，零偏移负载 R² 均 ≥0.9997，12 次 CPU 等待分离通过。后续 B32 非排名诊断的 3,600 个采样查询有效，记录及排空完整。最新同 APK 的 10 组/40 张冻结图覆盖 A/B、B32/B16、插桩 off/on、2/5/8 位、高重叠、129/256 和两个时刻，全部逐字节一致。

GPU 范围为 `HUD-camera-instrumented`：相机 BeforeForwardOpaque 至 AfterEverything 的查询区间，包含强制 render-pass store/resume 与查询开销，可能不含初始清屏，不含呈现和其他相机。已验证计时方法及画面；**尚未执行正式插桩影响 ABBA 和 13 组/52 轮 GPU 矩阵**。热状态持续为 3 的诊断轮不用于性能排名，不回填早期 APK 的 GPU 缺失值。

## 验证与适用范围

已有相关源码回归通过 190/190 EditMode、61/61 D3D11 PlayMode、251/251 治理记录；UIDataRender 行覆盖率为 90.0%（3,342/3,713）。预注册入口与设备诊断源码另有无 Library/无忽略依赖目录的干净验证。后续原生记录通路也通过 190/61 回归、包结构和损坏记录拒绝检查。本次归档只改文档、规格和工件跟踪策略，沿用这些适用的源码验证结果。

归档整理后，OpenSpec 全部 19 份主规格严格校验、包结构、251 条测试治理记录及变更文档的本地链接检查通过；无活动 OpenSpec change。218 个本轮新增原始工件已退出跟踪并在本地逐字节核对保留，未改动用户两份依赖文件。

C 因现有通用 holder 的 Color32 渐隐/顶点协议不能保持相同语义而 excluded；这不是 C 更慢的实测结论。D 仍为 not-integrated，A 不代表真实业务 ECS，未引入 Entities。其他 API、WebGL、URP、业务替换和主城全局约 10 次更新/秒留待后续独立验收。
