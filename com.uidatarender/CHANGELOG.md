Mean per-run Burst update median/p95 were 6.2247375/6.42495 ms custom and 8.5542625/8.74620 ms stock (+37.42%/+36.13%). Stock-related Unity validation passed 22 EditMode and 12 D3D11 PlayMode tests; governance remains 267 records. See [dependency-path conclusions and limitations](../Documentation~/perf-04-stock-scene-results-2026-11-11.md); budgets, target-device bytes and exact RC/coverage gates remain open.

- Add default-off rotating generation phase diagnostics with actual completed-holder aggregation, TMP Canvas/mesh/extraction/transform boundaries, explicit sample validity and per-frame Unity rendering dimensions. Preserve generation semantics and existing optional diagnostics; new GC acceptance uses Unity Profiler without adding runtime allocation counters. Original tests passed 205 EditMode / 65 D3D11 PlayMode; stock-related tests passed 9 EditMode / 12 PlayMode, alongside 267 governed records and 90.2% UIDataRender line coverage. Eight same-APK Mi 10 runs (72,048 frames) measure normal generation median 8.11815 ms; enabling full diagnostics increases Burst update median/p95 by 37.42%/44.12%, so phase values remain instrumented costs. A separate Editor/Mono Main Thread Profiler capture passes 39 byte/callstack controls and 906 HUD scopes with zero events/bytes; target bytes, other threads and full offline replay are not established. See [profiling conclusions and limitations](../Documentation~/perf-04-generation-profile-results-2026-11-10.md); PERF-04 budgets and release acceptance remain open.

- Add an opt-in Sample HUD workload with three repository Sprite textures, primary-atlas TMP text, deterministic bucket text snapshots, resource/build/UGUI provenance and hashed startup requests. Add positive-controlled bounded allocation-event diagnostics with separate event/byte availability and saturation handling. Initial validation passed 196 EditMode, 64 D3D11 PlayMode tests and 260 governed records. The November 7 Mi 10 measurements preceded the TMP fix below: mixed rotating Burst refresh update p95 was 10.7821–11.4473 ms and Development diagnostics observed allocation events during mixed refreshes. Device byte metrics remain unavailable. See [initial representative workload conclusions](../Documentation~/perf-04-representative-results-2026-11-07.md); no budget or release acceptance change.

- Add experimental shared-Quad damage-text instancing, visual/fixed/realtime comparison, separate draw/lifecycle stages, preregistered same-APK capture, JSON/CSV reports and independent validity checks. The original Mi 10 CPU/precision matrix completed 13 ABBA groups, 52 runs and 187,450 sampled frames; the change remains stage-archived at its historical 21/22 tasks. DAMAGE-03 subsequently completed a separate native GPU matrix of 13 groups, 52 runs and 187,464 valid samples. B32 instrumented HUD GPU run medians were 1.45–6.58% lower than A, while some draw-only p95 values were higher; A had lower lifecycle outer Update CPU. Complete-frame gains remain unverified. See [GPU follow-up conclusions](../Documentation~/damage-03-gpu-results-2026-11-06.md) and the [historical stage record](../openspec/changes/archive/2026-10-28-compare-damage-text-renderers/archive-record.md).

- Add opt-in local-XY Float16 storage, queried 68/64 B layouts and preparation-only capability/precision fallback. Device precision passed 32 cases/640 points: 24 FP16 cases and 8 correct Float32 fallbacks. FP16 reduced theoretical vertex capacity by 5.9% but increased lifecycle outer Update CPU by about 0.0327 ms; Float32 stays default. Art acceptance remains open.

- Add opt-in native Vulkan timestamp calibration and bounded capture with immutable commands, direct frame binding and query drain checks. Calibration passed all 1,680 required frames; a separate 3,600-frame diagnostic verified the capture path. Ten visual groups/40 images matched with instrumentation off/on. The follow-up accepted 16 instrumentation off/on runs and 52 formal GPU runs with thermal status 0; one interrupted 129 cohort remains environment-unverified, and its entire ABBA was rerun in a new registered session. FP16 showed no reliable GPU improvement and added about 0.061725 ms / 28.21% lifecycle outer Update CPU in the native matrix; Float32 stays default. Historical source regression passed 190 EditMode, 61 D3D11 PlayMode, 251 governed records and 90.0% UIDataRender coverage; these were not rerun for this measurement-only follow-up. Raw evidence and build intermediates remain local; Jenkins is outside this task's scope.

- Add opt-in fixed-atlas damage text with immutable 2–8 digit events, three styles, pixel-space GPU animation, persistent ordered mesh buckets, atomic publication/recovery and deterministic Clip playback. The Sample includes playback controls, three fixed recordings and traceable functional reports. First-phase validation passed 185 EditMode, 39 D3D11 PlayMode, 224 governed records and 89.4% UIDataRender line coverage. See the [playback contract](Documentation~/DamageTextPlayback.md) and archived `2026-10-26-add-damage-text-playback` specifications. Business ECS remains not-integrated.

- Add explicit holder snapshot queues and opt-in 2×128 two-frame rotation, atomic front/back publication, resource barriers and ordered Built-in camera draws. Local validation: 161 EditMode and 31 graphical PlayMode tests passed. The local 1.5 ms p95 goal passes; a 5.3688 ms peak, slightly higher two-frame total work and unavailable Android allocation counters remain explicit. See [bucket evidence](../openspec/changes/archive/2026-10-25-add-holder-bucket-scheduling/evidence/bucket-results.md).

The Sample can disable per-holder stage instrumentation independently of whole-update timers. Local regression: 150 EditMode and 29 PlayMode tests passed. Four Mi 10 comparison runs show 128-holder full-refresh p95 1.2971/1.2310 ms for query reuse versus 1.9776/1.9853 ms for live queries with identical diagnostic settings; the scoped 1.5 ms p95 target is met, while broader RC acceptance remains open. ### Fixes

- Reuse main-thread TMP extraction scratch with safe nested extraction, exception recovery and deferred explicit/runtime/editor cleanup. Preserve current geometry across changed and empty text in Managed and Slim storage. Positive-controlled tests reduce 128 warm extraction events to zero for fixed and changing inputs; full fixed/changing DoGenerate also records zero. Destination resizing and nested calls may allocate. Validation passed 204 original EditMode, 64 D3D11 PlayMode, 12 stock-related EditMode, 11 stock runner PlayMode tests and 265 governed records. Nine Mi 10 runs reduce bounded mixed HUD allocation events from 10,360 to zero with valid controls; bytes remain unavailable. Two Release runs per variant show an observed 8.32% reduction in mean Burst-refresh p95, with an interrupted sequence and no population/significance claim. See [device conclusions and limits](../Documentation~/perf-04-tmp-scratch-results-2026-11-08.md) and [TMP adapter contract](Documentation~/TextMeshProAdapter.md); overall PERF-04 remains open.

- Add a package-owned public-API index extraction fallback for stock UGUI while retaining compatible custom `CopyIndices` acceleration. Reuse and release scratch Mesh/List storage; cover topology identity, offsets, range checks, empty streams, warmed allocation, cleanup and the stock `<65,000` vertex limit. The clean runner prepares one reusable detached worktree under `D:/workspace/`, excludes custom UGUI, preserves real report provenance, and rejects empty/skipped results. VERIFY-02 passed in both dependency environments: 13 extraction tests, 196 complete EditMode and 61 D3D11 PlayMode tests each; governance 257/257. Actual stock source and calibrated zero-allocation evidence are recorded in the [acceptance conclusions](../Documentation~/verify-02-stock-ugui-results-2026-11-06.md). Performance budgets and release acceptance remain separate.

- Preserve bit-exact registered sample times across Unity JSON numeric roundtrips, reject coherent checksum/format/time corruption offline, defer final report allocation beyond sampled frames, and abort invalidated resources/configurations. Restore Sample lock-file inclusion required by clean validation and add `-WithGraphics` to the clean runner so graphical gates execute without weakening skip handling.

- Keep damage-text glyph orientation and upward motion consistent with GPU projection when rendering into textures; validate partial viewport visibility and expired resident glyph removal. The local validation script now supports `-WithGraphics` for actual D3D11 PlayMode acceptance.

- Close batch-cache geometry/cold-warm output coverage and Sprite-backed Managed/Slim equivalence; add explicit Sprite/fallback workload selection with configuration, path evidence and state/resource restoration. Regression: 147 EditMode and 28 PlayMode tests passed. Four device runs demonstrate equivalent Sprite paths without a reliable overall speedup. Four completed optimization changes and the unaccepted performance phase are archived under `openspec/changes/archive/2026-10-21-*`; PERF-04 remains open; subsequent bucket scheduling delivery is recorded above.

- Remove per-vertex Color32 boxing in Slim FillToDrawData/FillWithMatrix while preserving the all-zero color fallback and geometry output. Regression: 144 EditMode and 27 PlayMode tests passed. Four matched Mi 10 runs show Partial regeneration median reduced by 56.1–59.7% and Burst-refresh by 23.3–26.6%; overall performance/release acceptance remains open. Evidence: [Slim fill color check](../openspec/changes/archive/2026-10-21-optimize-slim-fill-color-check/evidence.md).

- Validate BuildMesh stage aggregation, nested accounting, stale-result clearing and warmed diagnostics-disabled allocation on Managed/Slim. The profiling specs are synchronized, and both profiling changes are archived under `openspec/changes/archive/2026-10-20-profile-buildmesh-stages` and `2026-10-20-profile-simple-quad-write`. Closure regression: 142 EditMode and 27 PlayMode tests passed.
- Restore opt-in Managed/Slim quad-write substage timing, clear stale diagnostic results, and distinguish unavailable samples from measured zero durations in HUD RC v2 reports. Local correctness/allocation/export validation and eight Xiaomi 10 comparison runs are recorded in `openspec/changes/archive/2026-10-20-profile-simple-quad-write/evidence.md`. Fine-grained timing materially increases measured write cost; overall performance and release acceptance remain open.
- Avoid repeated texture-version reads for stable null-Sprite Images and reuse the holder target Transform during mesh generation, preserving texture lookup when a Sprite is assigned later. Historical regression and device evidence: [null texture cache](../openspec/changes/archive/2026-10-20-optimize-uiimage-null-texture/evidence.md). ### Release rules

- Candidate versions use incrementing, non-reused `0.1.2-rc.N` versions and matching `v0.1.2-rc.N` tags.
- Each candidate must record its exact commit, validation evidence, and changelog entry; a failed candidate is followed by a new RC.
- Formal `v0.1.2` publication requires an accepted RC and explicit user confirmation. No tag or release is created by this governance update.
