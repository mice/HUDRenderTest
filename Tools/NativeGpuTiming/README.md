# Damage text native GPU diagnostic

Build the calibration with `Tools/Build-DamageTextComparison.ps1 -NativeVulkanProbe -ProbeInBenchmarkPackage`, or the opt-in formal recorder with `-NativeGpuTiming`, from a clean isolated checkout. The wrapper compiles this source with Unity 2022.3.53f1's installed PluginAPI headers and bundled Android NDK, records source/header/compiler/library hashes, temporarily imports the ARM64 library, and removes only that temporary asset after building. No prebuilt binary or Unity headers are vendored here. Ordinary benchmark and precision builds do not include the library.

Each of 640 diagnostic frames gets a unique immutable start/end command buffer pair and an encoded `(Unity frame, slot)` token. Start runs at `BeforeForwardOpaque`, end at `AfterEverything` after the extra load. Both events request an outside-render-pass state. Query reset/start/end are recorded into Unity's current Vulkan command buffer; the plugin never submits to the queue, enables debug layers, or flushes during sampling. Query slots are never reused. Polling starts only after Unity's `safeFrameNumber` covers the ending native frame, checks both query availability values, and omits `VK_QUERY_RESULT_WAIT_BIT`. Raw timestamps, hardware period/valid bits, call counts, native frame IDs, read/fence frame IDs, availability and status are exported.

The interval covers the instrumented camera render region, including render-pass store/resume overhead. Initial clears may precede it; presentation and other cameras are excluded. This calibration scene has only the HUD and explicit extra draws. It is not an uninstrumented whole-frame or production HUD timing claim. First establish complete, correctly bound perturbation response on the device; formal benchmarking and instrumentation overhead need separate evidence.

The query pool lives until graphics-device shutdown. Only shutdown waits for device idle before freeing it. The first configuration allocates all slots; subsequent configuration attempts fail rather than resetting in-flight storage. Unsupported graphics APIs/capabilities and native errors are explicit failures.

Formal recording uses the same unmodified native library validated in calibration v3. A preregistered request must explicitly enable `captureNativeGpu` and bind the calibration index SHA256. Its bounded pool and every immutable start/end buffer are allocated before Warming; at most 8,192 actual frames, at least 60 warmup frames, and 16 actual drain frames are required. Realtime requests must register a suitable bound (4,000 samples covers the 61.2 s/60 FPS clip). Per-frame command tokens are fixed in advance, and the runner defers its first Update to the registered next engine frame. After draining, JSON retains all camera/query records, status, availability and raw timestamps. Offline validation checks those against every formal sample and the calibrated library/device. Requests with recording disabled execute the same renderer without the plugin callbacks for independent image/CPU instrumentation checks. A new native segment requires a new process; slots are never reset for another session.

References: Unity's installed `IUnityGraphicsVulkan.h` API contracts and [official native plugin sample](https://github.com/Unity-Technologies/NativeRenderingPlugin), [Vulkan timestamp queries](https://docs.vulkan.org/spec/latest/chapters/queries.html#queries-timestamps). GPU timestamps measure elapsed device time; CPU clocks are used only to check injected sleeps and are never converted into GPU timings.
